## What was measured

**Everything below was checked against the tree, not assumed** — the
same exercise the last three vision files ran, with the same result: the
diff is much louder than the delta. Against the latest recorded design
state (v18 + v28 patches + the four later extractions + the 08-24

## 1 · Anonymous answers, private results — the first amendment D98 would notice

The design adds one 20px toggle (a glasses glyph) to the feed card and
the daily's world card: vote anonymously, and — the comment is the
spec — *"your pick still moves the count, but carries no name into
takes, faces, or friend cuts"*; the Mirror's answers browser stamps the
question with the same glyph and the sentence *"answered anonymously —
hidden when others view your map"*. A parallel toggle on the test result
banner (`TEST_PRIVACY`) makes a saved result private under the same
contract: *"default public; a private result stays yours."* The choice
is made at vote time and the design offers no post-answer toggle — an
answered card shows a stamp, not a control.

**This is a product-thesis question before it is a feature.** D98's
argument was that showing how one person's answers link to everyone
else's IS the product, and the previous owner-only model shipped most of
the Mirror dark. CLAUDE.md still says "Three denies remain, none about
answers." An anonymous option is not a return to that model — it is
per-answer, opt-in, default-public, and the counts stay exact — but it
is the first exception that IS about answers, and it subtracts exactly
the linkable data the Mirror draws. Whether that trade is wanted, and
on which surfaces (the feed and the daily's world card only, per the
design — never duels, where identity is the game and the seal is the
privacy), is the owner's call, recorded before any code.

**The honest live shape, measured against the rules.** The D98 read
rule is a value test — any signed-in user reads an answer whose
`surface` is in the public list, and every cross-user query must carry
a matching `where("surface","in",[…])` filter or be refused wholesale
(the D65 lesson). That shape hands this feature its implementation:

- **An anonymous answer writes a surface value outside the public
  list** (`daily-anon` / `feed-anon`). Every existing reader — named
  who-voted, compare, the person map, "people like you" — excludes it
  *without changing a line*, because their list filters already name
  only the public surfaces. No read-rule edit, no backfill, no new
  reader discipline to enforce.
- The alternative (an `anon: true` field + `!= true` value tests) is
  worse in exactly the way Firestore is: a `where("anon","==",false)`
  filter drops every existing answer that lacks the field, so it
  demands either a backfill or a default written forever. Name this in
  the decision record so nobody re-proposes it.
- **The aggregate trigger folds the anon surface exactly like its base
  surface** — that one trigger change is what makes "they still count"
  true. Population counts stay exact; the Mirror's folds, the Oracle's
  grading and typicality never notice.
- **Create-only survives untouched.** Anonymity is chosen at vote time
  and immutable after, which is the design's own UI; D86's
  `optionIdx`-only edit stays as it is (an edit moves the vote, not the
  name). Do not add an anonymize-later path without reopening D86 —
  a mutable privacy field on an immutable answer is a second update
  shape.
- **The owner still sees their own** (`uid == uid` reads everything),
  which is what the Mirror's own-answers browser needs to draw the
  stamp.

**Result privacy is the same contract on a different object, and it is
weaker — say so.** The four core tests are passive: their inputs are
ordinary `surface: "test"` answers, which are public. Hiding the
*result* while its constituent answers stay public hides the
projection, not the inputs — a determined reader can re-derive it. The
honest live shape is absence, not filtering: a private result's scores
are **not written to the profile projection others read**, which also
means the person drops out of strangers' kindred rankings and score
compares (the similarity field ranks by test-score match — a private
result has to cost that, or it is not private). The account-panel copy
must promise only what this delivers. If the owner wants the stronger
promise, test answers need the anon surface too, and that is a bigger
sentence.

**The paperwork is not optional, and it is most of the work:**

- The D183 account-panel copy ends today with "Nothing you answer here
  is private." — a sentence this feature makes false the day it ships,
  so the panel's one blunt statement gains its one qualifier in the
  same commit as the rules, and `web/privacy.html` says the long
  version once. Both claims get `check:policy-claims` rows: the UI
  promise ("hidden when others view your map") must be provably backed
  by the rules/trigger behaviour, which is what that gate exists for.
- `check:public-copy` sweeps the new copy — the retired pre-D98
  vocabulary lives there; check the new sentences against its list
  before writing them into the panel.
- The demo keys (`insight.dailyq.anon.v1`, `insight.feedAnon.v1`,
  `insight.testPrivate.v1`) are prototype furniture. Live state lives
  on the answer doc itself; any local mirror joins the purge sweep
  (`check:purge`).
- Rules tests in both directions (a stranger's list query cannot see an
  anon answer; the owner's can; the aggregate still moved), and the
  erasure e2e leg unchanged (anon answers are still the owner's docs).

**Cost:** zero new reads — the surface-value shape rides every existing
query. The costed item is the decision itself: every anon answer is one
the People lens, compare and the voter lists cannot draw.

## 2 · The paid family — the market grows a law, subscriptions grow seats, and the catalog gets a window

Four moves that read as one page. The demo store's comments are
unusually explicit this round — they read like the PAID-PLAN amendments
they are asking to be.

### 2.1 · The market's law (adoptable now)

`paid-data.js` writes four rules the tree's pricing does not have:

1. **Intersections price at the max of their parents' indices.** *"An
   intersection consumes inventory in every parent pool, so it prices
   at the MAX of its parents' indices — a thin cell is never a
   discount."* Today `data/pricing.ts` rates single cohorts;
   dimension-narrowed asks (D228's chips) change reach, not price.
   The amendment: per-dim indices join `content/pricing.json`, `rate()`
   takes the max over the scope + dims, `check:pricing` holds the
   bound, and the door prints the resolved line before the contract
   sheet.
2. **`minTicket`** — the 500-answer week floor × the line is the
   honest entry price, printed on the rate card ("Minimum ticket: …").
3. **`shareCap` 0.3** — no buyer holds more than 30% of a cohort's
   person-days in a window. An anti-capture rule; it belongs in
   PAID-PLAN §6 and in the operator's booking script as a refusal, not
   in client code.
4. **`atClose`** — a booking picks its short-at-close behaviour:
   extend free until met, or settle for what arrived (never the cap —
   billing is per answer, D164). One field on the purchase record; the
   room prints the chosen sentence.

All four are copy + one committed artifact + one script; none needs a
new collection. The under-floor counter-offer the comment sketches
("widen an age band, add a neighbour city — a refusal converted into a
booking") is operator guidance, not code.

### 2.2 · Seats and pledges (owner decision)

`SUB` reprices PAID-PLAN §5's subscriptions as a **forward contract on
the same market**: a panel of answers each period × the posted line,
−20% for the standing commitment — and then the actual mechanism
change: **because results are public, a metric's period cost splits
evenly across its subscribers** (€24 seat floor, recomputed each
period), *"the second subscriber halves the bill instead of buying it
twice"*. Inactive catalog metrics take **pledges** and go live the day
pledges cover a period. A lapse drops one seat; if others still fund
the metric the series runs on (the room draws your post-lapse days in
grey); only the last seat's lapse pauses it, history kept either way —
which is §5's standing lapse rule, now with a seat count in front of
it.

This is better economics than §5's one-buyer shape (public results
made the single-buyer price a free-rider invitation), and it is more
machinery: seat membership, per-period splits, pledge escrow and its
refund story, and a billing recompute — all server-side records in the
`v2_purchases` family, none of which exists. **PAID-PLAN §9's
demand-first sequencing still applies**: D288 §3 built the mechanism's
committed-price half ahead of demand, but seats and pledges are worth
building the day there are two would-be subscribers for one metric,
and not before. The decision to record now is the *pricing model*
(split vs per-buyer), because the catalog sheet's copy prints it.

### 2.3 · The shop window (`catalog-sheet.jsx`, new)

One read-only overlay: metrics grouped by place with
active / pledged / inactive states, the co-funding arithmetic said in
one card, the one-off market's rate table (with the intersection row
priced at the max, the booked share, the floor/ceiling sentence), the
author-a-metric card — *"written ahead, kept neutral by editorial …
the scorecard set stays editorial and unbuyable"*, which is D228's
boundary spoken to a buyer — and the contract path as two mail
addresses. *"No checkout here, deliberately"*: the shipped door's
"arranged directly" posture, extended, and the reason the sheet can
exist in the iOS build at all. Doors into it: `openCatalog()` from the
shell, the place scorecard's "+ Author a metric" foot, and §2.4's
tail. Prices read the committed `content/pricing.json` like the door
does; the demo `CATALOG` never ships (D167) — with no real metrics the
catalog section states that and the mail path stands alone.

### 2.4 · "Asked for {place}" — the Mirror tail (waits on its own data)

Under the City/Country/World Answers lens: every paid question scoped
to the place (PAID band, onto its report page) and every active metric
(METRIC chip, onto the catalog), one bordered list under the answer
record — the *"separate, disclosed band"* shape D228 reserved, in the
spot D228 reserved it for, and the extraction's comment cites the rule
("tail, never core"). D228's condition was "when a real subscription
exists": build the tail so it renders only rows that exist, and it
satisfies the condition by construction. The one open call is the
empty state — the design shows *"Nothing runs for {place} right now —
the catalog takes pledges"* plus the ask-a-question door, which is an
advertisement on a Mirror stop. Ship the tail with rows; ask the owner
about the empty-state door before mounting that half.

## 3 · The Oracle's working — the sealed call rebuilt in the open — BUILT (D310)

Today's live "why?" shows up to two tells — real crowd readings with
their D146 basis. The design replaces the surface with **the working**:
the sealed reading rebuilt from the same answers *with this question
held out*, up to three contributing answers of yours, each drawn as
"You said **X** — 'prompt'" over a bar of the crowd split it
contributed, against a hairline at the coin, weighted by its actual
pull on the call — under the standing basis line *"sealed before your
tap · counted only from answers you'd already given · the mark is the
coin."* The empty case stops being a shrug and becomes a claim: *"it
guessed at the coin, and the empty disc says so."*

Measured against `data/patterns.ts`: the device solve that sealed the
call already computes per-question contributions; `working(qid)` is a
hold-one-out re-solve (8-dimensional ridge — microseconds) plus the
tell fetches the lens already makes, bounded the same way (≤3 rows,
on demand, after reveal). **The seal's pinned timing must not move**:
the working renders only in the revealed state's why-view, computed on
tap, and stores nothing — the pin (`src/v2/data/patterns.test.ts`)
should not need to change, and if a diff touches it, the diff is
wrong. The D287 refusal on "N from feed votes" is untouched — that
count is provenance the store does not record, and the working makes
no such claim.

**As built (D310):** `PATTERNS.working` reads the GRADE's own evidence
list (now top-3) through `tell()`'s session caches — at most three
bounded fetches — and keeps only rows whose tell clears the 0.54 floor
the single line always used. Two sentences shipped corrected: the
no-evidence case says *"the call is the crowd's own lean, and the faint
ink says so"* (the live fallback is the marginal, not the coin, and the
disc is faint, not empty), and thin evidence gets its own state (*"under
12 in both samples"*) instead of being dressed as absence — a case the
prototype's invented crowd could never produce. The pin never moved;
`patterns.test.ts` grew five working cases.

Alongside it, from the same files: the ledger's standing one-line key
(`.or-cap` — "you broke its guess · it had you · tap to recall"),
which keeps true what the one-time hints teach; the dashed landing
seat sized to the disc (`--d`), still identical both sides so nothing
leaks; and the tile's label centred by grid row. All
`ui/PatternsOracle.tsx` + `ui/patterns.css`.

## 5 · Play together — the person overlay grows its doors — BUILT (D310)

A new card between the receipts and the 1v1 record, for non-anonymous
people: a **1v1 row** — Open (jumps to your running duel), invited
(waiting on them, cancellable), Start (for friends), or "for friends —

do not already draw; the same `MIN_DUO`/`MIN_GROUP` floors gate it.

## 6 · The feed's friends learn participation — a demo honesty pass — BUILT (D310)

`wfDid` gives each demo friend an activity share and shows them on a
question **only if they answered it**: most cards carry 0–2 friends,
many none — *"that silence is what keeps friend marks from becoming
furniture."* Every friend surface learns the empty state ("None of
your friends has answered this one yet"), the stats sheet names who
hasn't, the insight line goes singular ("Alex disagrees"), the option
rows draw real mini avatars in per-friend hues (two + overflow), and a
`friends` opt adds a footer placement (identity docked by the vote
count) beside `rows` and `off`.

Measured against the tree, this is **the demo modelling the restraint
the live app already has by construction**: live cards draw no friend
marks at all (`q.live ? []`), because a friend's real vote on a card
is a read nobody has priced — the voter lists are fetched per-sheet,
not per-card, and SCALE-PLAN's arithmetic is why. So the port is:

- **Port to the demo layer**: `wfDid`, the empty states, the singular
  line, the avatar drawing on `rows` (the shipped default look — the
  hue avatars are what a user would eventually see live, so the demo
  should model them).
- **Do not port** the `footer`/`off` arms — a tweaks-lab comparison
  control; the app dismantled the lab (same verdict as `friendVotes`
  at 08-24, which this control extends).
- **The live half stays refused** until someone prices per-card friend
  votes (a circle-sized query per card, or friend votes riding a feed
  the server already folds). That pricing is a SCALE-PLAN note, not
  this plan's work.

The demo `feedInsight` singular-phrasing does not apply at all: the
app's live `feedInsight` refused the `friends` kind outright at D287,
returns null on demo cards, and keeps both refusals — there is no line
to make singular.

**As built (D310):** `wfDid` + the empty states + the who-hasn't line +
the identity avatars (through `WPAL.ink`, per-friend hues), on tiles in
BOTH drawings — deliberately superseding the ported "v2 drops them from
the tile" comment, because participation answers the furniture problem
that judgement was about. `footer`/`off` not ported; the `q.live` gate
untouched.
