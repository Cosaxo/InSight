# Launch content

Canonical question banks and taxonomies, extracted from the v9 design
prototype (deleted 2026-07-29; in git history — `design/InSight_standalone_18.html` is the current reference). These files are the source of
truth for seeding Firestore: `scripts/gen-v2content.mjs` flattens them into
`functions/src/v2content.ts` (regenerate with `npm run build:content`),
which the `seedContentV2` callable compiles in. `npm run check:content`
regenerates in memory and compares bytes on the deploy path, so the two can
never drift silently. After launch the live Firestore documents become the
operational copy (editable without a redeploy, per the taxonomies pattern).

**Everything here is read by something, and `check:content` enforces it**
(D137). The banks below are the generator's inputs — the list lives once,
as `CONTENT_SOURCES` in `gen-v2content.mjs` — and the two files that are not
inputs are named in `check-content.mjs`'s `NOT_SEEDED` with the reason. A `.json`
that is neither fails the check. It is a real failure, not tidiness:
`archetypes.json` sat here unread long enough to diverge from the live source
it mirrored, so editing it looked like changing the app and changed nothing.

| File | Contents |
|---|---|
| `daily-questions.json` | The daily World question pool (140) — scale / binary / choice / rating / dilemma types |
| `feed-questions.json` | Feed questions (515) + topic (11) and channel (4) definitions. Three optional fields ride here and nowhere else: `until` (the serving window, D179), `core` (the Mirror's corpus — absent means TAIL, D161) and `sponsor` (the paid block, D195/D228: an optional buyer name — companies or individuals, nameless allowed, the PAID band renders regardless — and one to three coarse audience tags the device matches conjunctively; none are set today, deliberately) |
| `pick-questions.json` | Live catalogue-pick questions (D14/D232) — "favourite X from a shipped catalogue", `type: "catalog"` on the feed surface, answers are `entity` keys the trigger validates per-domain. **Filled only by `npm run promote` from the pick archive** (`src/v2/spec/pick-data.js`); `check:quality` holds seed and archive byte-equal by id, and `check:content` refuses any domain without a committed catalogue under `public/` — films joined that set at D266, athletes at D308, artists is still absent (D267) |
| `duel-questions.json` | Group daily bank (74: a CAST since D434, the owner's 2026-09-08 design — twenty-six role votes, `pick` questions naming the scenario pack (`scen`, one of the six in `scenarios` — the sixth, *Any Given Evening*, is four of the older pick-a-member questions given a role and a seat in place, qids kept, D444), the role they cast and its `seat` (engine · hands · heart · wild, D437 — each pack one role a seat, two roles retired and replaced to make it so); ten `rate` questions between two `poles` whose five step labels are derived at seed time; and the 30 questions in the older shapes (about-us / pick-a-member / classic — the lane appended eight of them on 2026-09-09, before its contract changed), all in the bank and out of the rotation: eleven retired (`active: false`) — five because a rating re-asks them, six pick-a-member ones the sixth pack's one-role-a-seat could not hold (D444) — and the rest dealt by nothing since the cast). 1v1 bank (49) and the romantic 1v1 pool (43, `mode: "romantic"` — seeded `active: false` until the mode-aware client is the fleet, D40 part 4), each ending in its one `cast` round (*Most days, {name} is…* — four answers with an axis and a *them* form, dealt every fourth round, D437); the last two share the `duo` surface, 92 together. Single source since 2026-08-03 (the D32 learn-data shape): the seed reads it whole, and the demo layer reads its generated sample (`duel-sample.json`, below) — so demo and seed cannot drift, and since D435 the bank itself is no longer compiled into the app |
| `duel-sample.json` | **Generated, never edited** (D435, D284's shape one bank over): the fixed slice of `duel-questions.json` that `src/v2/spec/duels-data.js` imports for the demo build — the first `PER_KIND` served questions of each group kind and the first `PER_DOMAIN` of each 1v1 domain, in bank order, plus the scenario packs those role votes name. Stable under append, so the lane's runs never move the bundle; a retirement does move it, and `check:duel-sample` says so. `npm run build:duel-sample` regenerates |
| `tests.json` | The four core tests' item banks (big5 · political · values · attachment): the 110 core items in `questions`, mirrored item for item by `src/v2/spec/test-definitions.js` (`content-parity.test.jsx`), and since D416 the **deep items** in `deep` — the Big Five's thirty facets (four items each, two keyed against, the app's voice) and the compass's eighteen positions (two each, the 2026-09-07 design's own) — declared in `facets` and carried **bank-only**: `facet` + `invert` ride the seeded document and the device joins them by id (`data/similarity.ts` `testDeepMeta`), so 156 prompts stay out of first paint. The lens items continue the same seq counter after them; the deep items after the lenses, so no shipped seq moved |
| `lenses.json` | The nine lens banks (moral · risk · trust · time · taste · conflict · humor · thinking · culture) — the client minted these ids |
| `learn-questions.json` | Learn subjects, fields and cards (246) |
| `learn-sample.json` | **Generated, never edited** (D284): the fixed slice of `learn-questions.json` that `src/v2/spec/learn-data.js` imports for the demo build — `PER_FIELD` cards a field in bank order, the subjects and fields whole. `check:learn-sample` holds it to its source; `npm run build:learn-sample` regenerates |
| `pulse-questions.json` | The daily pulse's TEMPLATE questions (D139) — one doc per pulse question forever, never one per day; answers are keyed `{qid}_{day}` against them. Exactly five ordered steps each, because the trends chart's y-axis IS that scale |
| `call-questions.json` | Foresight CALL, tier A (D194) — sealed predictions graded against this app's own published aggregates. **Every entry is `active: false` (D196)**: the owner wants predictions about real EVENTS, and these predict our own numbers. Kept whole because a real-event rubric is a new `kind` on this schema, not a new feature. `check:calls` still dry-runs every one. Editorial-only, like the pulse bank, so no provenance rows |
| `ads.json` | Feed ads (D197) — docs/MONETIZATION.md **path 3**, and NOT path 2's sponsored questions: an ad is a CARD that takes no answer and produces no data, where a sponsored question is answered like any other and folds into the public aggregate. Text only, no link, one coarse audience tag matched on the device. **Ships empty, deliberately** — writing one means printing a real company's name on a card nobody bought. Seeded to `v2_ads`, its own collection |
| `provenance.json` | Who wrote each daily/feed question and in which vintage (D97) — written by `promote-questions.mjs` and the lane PRs, held in step with the banks by `check:quality`, read by the scorecard's `production` rollup. Measurement metadata, not content — never seeded |
| `topic-proposals.json` | The taxonomy ledger (D424, D425, D427) — questions a lane met that fit nothing below their nearest parent, parked with their run dates rather than dropped, plus `retag` (existing questions a proposed leaf claims) and the `created` rows. Read by `npm run topic:budget`, which rules per proposal — a **leaf** (feed subtopic, learn field: evidence · parent levelled · one leaf per parent at a time) or a **top**, which must land in a hub that already exists on the You map (`group`; a hub that does not exist is the owner's call) — and validated by `check:taxonomy`. The path out is `retirements` → `retired` (D427): a room is **folded** into another — its questions re-homed, never deleted — and `check:taxonomy` fails a retired id found at any site. **Ships empty, and that is its correct state**: proposals accumulate from runs, they are not seeded. A parked question reaches no bank until its room exists and it is written into one. The path out is `retirements` → `retired` (D427): a room is **folded** into another — its questions re-homed, never deleted — and `check:taxonomy` fails a retired id found at any site |
| `scorecard.json` | Generated measurement output for the scorecard renderer (`npm run scorecard`) — an output, never an input to the bank |
| `artist-review.json` | Hand-reviewed exceptions to the artists catalogue's mechanical rule (D267) — build input for `scripts/build-catalog.mjs artists`, never seeded. The rule keeps anyone at least a third of whose Wikidata occupations are musical, which is the best mechanical cut measured and still drops Wagner while keeping Henry VIII; this is where a human overrules it. Ships **empty** — the ruling is the owner's. `check:catalogs` holds every entry against the committed catalogue in both directions |
| `athlete-review.json` | The athletes catalogue's reviewed exceptions (D308) — the D267 machinery one domain over, same rule (≥⅓ of occupations athletic), same gates. Ships **filled**: the unrefined ranking led with George W. Bush and dropped Serena Williams and Pelé, so the first ruling landed with the catalogue — 20 admits (sport legends whose P106 grew past the ratio) and 1 reject, each auditable by name |
| `pricing.json` | The published rate card (PAID-PLAN §6, D288 §3) — the standing constants (base €/answer, the floor multiplier — `floorX`, and no ceiling since D373, whose own title is "The index is crowding, with no ceiling"; `ceilX` exists nowhere in the tree — the weekly floor, the cap, FX) plus the demand-derived half (per-cohort idx, the next-14-days booked ticks, estimates withheld until a cohort has a completed campaign). Imported by `src/v2/data/pricing.ts` — **the committed file IS what the door prints**, so a price change is a reviewed diff — refolded from the purchase ledger by `scripts/build-pricing.mjs`, held to shape by `npm run check:pricing`. Never seeded: a rate card is not a question bank |

Provenance notes:

- Extracted mechanically from the spec's data modules (`daily-questions.js`,
  `world-feed-data.js`, `duels-data.js`, `test-definitions.js`,
  `sample-data.js`).
- Two extractions did NOT survive and were deleted in D137: `archetypes.json`
  and `scenes.json`. Nothing ever read either, and the modules they mirrored
  — `src/v2/spec/archetype-data.js` and `scenes.js` — are the live source,
  hand-edited since. Same call as `design/spec-modules/` (deleted 2026-07-29
  once the copies had diverged); both are in git history.
- Synthetic *crowd distributions* from the prototype are intentionally **not**
  extracted — live counts come from real answers. Seeded demo comments are
  excluded per decision D1 (no synthetic users).
- Copy in these files is the canonical product voice; edit deliberately.
